# persona-pipeline-demo

人物ごとの文章からAIペルソナを作り、同じシナリオと質問に答えさせ、回答の形式を機械で確認して分類し、分析できる形のデータセットにするまでの手順を、実際に動かして見せる小さな公開デモです。

**ここで作られるものはすべて、架空の自伝から作ったものです。研究上の意味はなく、何かの検証でもありません。**
公開デモが示すのは、手順が最初から最後まで動くこと、そしてモデルに送った送信本文が1件ずつ記録され、固定したテンプレートと照合されることです。仮説の検定は行わず、検定統計量も計算しません。

## 1. 公開リポジトリの中身

| 部分 | フォルダ | 内容 |
|---|---|---|
| 処理プログラム（engine・汎用） | `engine/`, `demo.py` | 送信本文の組み立て、送信、回答形式の確認、分類、データセット作成、監査を行うPythonコード。テンプレートは含まない |
| プロジェクトのひな形（入力は空） | `projects/_template/` | 自分の文章と経験指標の表を入れる場所。`templates/` に日本語のテンプレートとSHA-256の記録がある |
| 公開デモ用の例 | `projects/demo_synthetic/` | 架空の自伝、架空の経験指標の表、保存した回答（`outputs_example/`）。経験指標の表の値は、文章を書く前に**著者が設計表として与えたもの**で、文章から判定したものではない。6本のうち2本（D05・D06）は、経験指標の手がかりを文章に置いていない |
| テスト | `tests/` | 再生モードの自動テスト（GPU・モデル不要） |
| 道具 | `tools/` | push前の検査（`check_forbidden.py`） |

本研究の実データはこの公開リポジトリに**含まれません**。`projects/_template/` の入力は空、`projects/demo_synthetic/` の入力は架空の自伝です。

テンプレートのファイルは、本研究で固定した指示文などの文書から、区切り線の内側（実際にモデルへ送った部分）だけを抜き出して作りました。文書のヘッダ欄は写していません。

送信本文は日本語です。英語の参考訳は `templates/reference_translation_en/` に置けますが、生成にも、ハッシュにも使いません。

## 2. 実行の2段

1. **再生モード（モデル不要・数秒）**：`projects/demo_synthetic/outputs_example/` の保存した回答を使います。

   ```
   pip install -r requirements.txt
   python demo.py replay
   ```

   最初に `manifest.json` と現在のテンプレート・文章・設定を照合し、違いがあればそこで止まります。続いて全送信本文を組み立て直して保存済みの台帳とSHA-256を突き合わせ、回答形式の確認、保存した分類結果の読み込み、データセット作成、監査を行います。不合格の回答は、データセット作成より先に表示されます。自動テストも、小さなテスト用データ（`tests/fixtures/`）でこのモードを実行します。

2. **生成モード（自分のPC・任意の接続先）**：`config/demo.yaml`（`generation.base_url`、`generation.model`、必要なら `coding.*`）を編集し、順に実行します。

   ```
   python demo.py check
   python demo.py build
   python demo.py generate        # 送信します。モデルのサーバが必要
   python demo.py accept
   python demo.py code
   python demo.py dataset
   python demo.py audit
   ```

   必要なら、`python demo.py snapshot` で終わった実行を `outputs_example/` に写し、`manifest.json` を書きます（再生モードで使えるようになります）。既存の `outputs_example/` は先に削除されます。

   既定のモデル名は `gpt-oss-20b` です。保存した回答は、研究用クラスタのNVIDIA H200（141GB）1枚でvLLM 0.30.0（`--reasoning-parser openai_gptoss`）を使って生成しました（`projects/demo_synthetic/RUN_RECORD.md`）。他の接続先では、必要な計算機の条件や推論部分の分離の仕方が異なる可能性があります（ここでは未確認）。鍵は設定に書かれた環境変数から読み、ファイルには書きません。

### 再現性の2層

- **再生モード**：送信本文、そのSHA-256、回答形式の確認結果、データセットを厳密に再現します。
- **生成モード（生成からやり直す）**：同じ手順で新しい標本を得ます。出力は保存したものと一致しなくてかまいません。接続先が違えばseedは同じ出力を保証しません。文章やテンプレートを直したときは、保存した回答が新しい送信本文に対するものでなくなるため、作り直しが必要です（再生モードは止まって知らせます）。

## 3. 処理プログラムの流れ

0. **入力**：人物ごとの文章（`inputs/texts/<person_id>.md`、匿名化済み）、経験指標の表（`inputs/persons.csv`）、テンプレート、設定。
1. **組み立て**（`build`）：ヘッダ + ペルソナブロック + シナリオ + 質問 + 出力形式を空行で連結します。組み立ての前に、テンプレートの全ファイルを `templates/frozen_hashes.csv` と照合します（一致しなければ止まります）。送信本文のSHA-256を `ledger.jsonl` に記録します。条件は `C3`（本人の自伝）、`C0`（自伝なし）、`C3W`（別の経営者の自伝。次の人物の文章を1つずらす巡回で割り当てる）、`C3-mixed`（混合自伝。本人のエピソードを、文字数が最も近い別の経営者のエピソードで1つずつ置換。乱数なし）。
2. **生成**（`generate`）：送信前にもう一度、台帳のハッシュと照合し、1通のユーザーメッセージとして送ります。temperature 1.0、top_p 1.0、max_tokens 8192、seed = `seed_base` × 100 + 反復番号。`reasoning_effort` は独立した設定で、記録されます。実際に送った本文と応答を1件1ファイルで保存します。
3. **回答形式の確認**（`accept`）：7基準（JSONとして読める／キーがちょうど7つ／q1は相異なる3記号／q2の分類番号が範囲内／q3は4択／q5は5者の順列／自由記述3つが非空）。不合格は作り直さず、`rejects.csv` に記録します。
4. **分類**（`code`）：3つの自由記述を、変数ごとの別のプロンプトで分類します。分類に使うモデルに渡すのは当該の文だけで、人物・条件・モデル・シナリオは渡しません。分類の接続先は生成と別に設定できます。既定では生成と同じモデルです（簡略化）。
5. **データセット作成**（`dataset`）：`dataset_A.csv`（1回の生成ごとに1行：`person_id, condition, model, scenario, rep, accepted`、構造化した回答、分類の値）と `dataset_B.csv`（人物ごとに1行：`persons.csv` の列）。結合キーは `person_id`。`C0` の行は `person_id` が空です。
6. **監査**（`audit`）：台帳・送信ファイル・出力記録を突き合わせ（件数とハッシュの一致数を表示）、あわせてテンプレートから本文を組み立て直して独立に照合します。

出力の値（選択肢など）は日本語のままです。自由記述は、モデルが英語で書くこともあります（保存した実行では144件中2件）。

## 4. 本研究との対応

| 公開デモの段 | 本研究の工程 | 簡略化した点 |
|---|---|---|
| 組み立て・ハッシュ照合 | 固定したテンプレートからの機械組み立て、送信前照合、台帳記録 | 同型（移植） |
| 生成 | 研究用クラスタ上の公開モデル、数千件 | 小さなモデル1つ、保存した実行は144件。`reasoning_effort` は新しい自由度 |
| 回答形式の確認 | 7基準、不合格は記録のみ | 同型 |
| 分類 | 別系統のモデル、4変数、当該文のみ | 既定は生成と同じモデル（分離可）。変数は同じ4つ |
| データセット | 別スクリプトで構築した大きなデータセット | 最小の2表 |
| 分析 | 混合モデル（人による照合の後） | **含まない** |
| 長期志向の測定 | 抽出→一対比較→Bradley–Terry | **v1では含まない** |

`templates/frozen_hashes.csv` のSHA-256は、この公開リポジトリのファイルのハッシュです。本研究で固定した記録の値とは別物で、一致しません。本研究のコードブックは同梱していません（別途追加予定）。ここでの文章は3,000〜5,000字ほどで、本研究の文章よりずっと短いため、実行時間とモデルの挙動は異なります。

## 5. 自分のデータで使う

`projects/_template/README.md` を見てください。要点は、`projects/_template/` を `projects/<自分の名前>/` にコピーし、匿名化した文章を `inputs/texts/` に入れ、`inputs/persons.csv` を埋め、`config/demo.yaml` の `project:`（または `--project`）でそのフォルダを指し、`python demo.py check` を通すことです。
差し替えられるもの：文章、経験指標の列、シナリオ・質問・出力形式のファイル、条件の選択、反復数、接続先、パラメータ。
この版で変えられないもの：組み立ての順序、ハッシュの記録と照合、7基準の構造（値の集合だけ設定で変更可）、監査の型。
テンプレートのファイルを変えたときは、`frozen_hashes.csv` を意識して作り直してください。設定のパラメータは `generation_params.yaml` と一致している必要があります。

## 6. 限界と、確認していないこと

- 保存した回答（`outputs_example/`）は、実際の1回の実行（vLLM + gpt-oss-20b、GPU 1枚。`projects/demo_synthetic/RUN_RECORD.md`）から作りました。自動テストは今もダミーのクライアントと小さな固定データを使い、モデルには接続しません。
- 他の接続先が推論部分を回答に混ぜないかは確認していません。保存した実行では、推論部分は別の欄で返り、回答に混ざったものはありませんでした。
- 保存した実行の144件のうち2件は、回答形式の確認の基準1（JSONとして読めない。閉じ引用符が `"` ではなく `」` だった）で不合格でした。手順どおり `rejects.csv` に残し、分類とデータセットAの合格行から外しています。
- 保存した実行では、送信本文とseedが同じ行は同じ回答になることが多く、144件のうち異なる回答は101件でした（C0の36行は9通り、C3Wの36行のうち16行はC3の回答と同じ）。144件は独立した回答ではありません（`projects/demo_synthetic/RUN_RECORD.md`）。
- 既定の分類は生成と同じモデルです（簡略化）。
- 架空の自伝では、実データの知見が再現されることは示せません。

## 7. 現在地・由来・確かめ方

- **版**：タグ `v0.1-stage1` は、匿名審査中のStage 1提案に添える版です。著者名と引用情報は後の段階で加えます。
- **動作を確かめた環境**：Windows 11（Python 3.12.10）では `python -m pytest`、`python demo.py check`、`python demo.py replay`、`python tools/check_forbidden.py` を実行しています。GitHub Actions上のUbuntu（Python 3.12）では `python -m pytest`、`python demo.py check`、`python tools/check_forbidden.py` を実行しています（pytest の中の再生テストは小さなテスト用データを使い、`projects/demo_synthetic/` の再生ではありません）。
- **保存した実行**：`projects/demo_synthetic/RUN_RECORD.md` に、モデルの版、サーバの版、生成パラメータ、件数、時間、不合格2件の内容を記録しています。
- **架空の自伝**：6本はこの公開デモのために書き下ろしたものです。`projects/demo_synthetic/WRITING_NOTES.md` に執筆の規律と点検（年号・実名・実在の出来事を置かない）を記録しています。本研究の文章との12字一致が0であること、本研究の固定した再同定指示文で商用3モデルに問うても本研究の人物を挙げなかったこと（事前に定めた判定規則で90試行中0件）も確かめています。
- **改ざんの検知**：`projects/_template/templates/frozen_hashes.csv` と `projects/demo_synthetic/outputs_example/manifest.json` にSHA-256を置き、`python demo.py replay` はテンプレート・文章・設定のどれかが保存時と違えば止まります。
- **含まれないもの**：実在の自伝、実名、実データの回答、本研究の仮説を検定する分析コード。審査中の問い合わせは、学術誌の編集部（査読過程）を通じて著者に届きます。
