# [リポジトリ名: 未定]

人物ごとの文章から AI ペルソナを作り、同じ状況と質問に答えさせ、回答を機械で検収・コード化して、分析できる形のデータセットにするまでの手順を、実際に動かして見せる小さなデモです。

**ここで作られるものはすべて、架空の合成文章から作ったものです。研究上の意味はなく、何かの検証でもありません。**
デモが示すのは、手順が最初から最後まで動くこと、そしてモデルに送った文面が1件ずつ記録され、凍結した雛形と照合されることです。仮説の検定は行わず、検定統計量も計算しません。

## 1. リポジトリの中身

| 部分 | フォルダ | 内容 |
|---|---|---|
| 装置（汎用） | `engine/`, `demo.py` | 送信本文の組み立て、送信、検収、コード化、データセット作成、監査を行う Python コード。文面は含まない |
| 雛形（空） | `projects/_template/` | 自分の文章と属性表を入れる場所。`templates/` に日本語の文面と SHA-256 の記録がある |
| デモ用の例 | `projects/demo_synthetic/` | 架空の文章、架空の人物表、保存した回答（`outputs_example/`）。人物表の属性の値は、文章を書く前に**著者が設計表として与えたもの**で、文章から判定したものではない。6本のうち2本（D05・D06）は、属性の手がかりを文章に置いていない |
| テスト | `tests/` | 再生モードの自動テスト（GPU・モデル不要） |
| 道具 | `tools/` | push 前の検査（`check_forbidden.py`） |

本研究の実データはこのリポジトリに**含まれません**。`projects/_template/` の入力は空、`projects/demo_synthetic/` の入力は合成です。

雛形のファイルは、本研究の凍結した文面の文書から、区切り線の内側（実際にモデルへ送った部分）だけを抜き出して作りました。文書のヘッダ欄は写していません。

モデルに送る文面は日本語です。英語の参考訳は `templates/reference_translation_en/` に置けますが、生成にも、ハッシュにも使いません。

## 2. 実行の3段

1. **再生モード（モデル不要・数秒）**: `projects/demo_synthetic/outputs_example/` の保存した回答を使います。

   ```
   pip install -r requirements.txt
   python demo.py replay
   ```

   最初に `manifest.json` と現在の雛形・文章・設定を照合し、違いがあればそこで止まります。続いて全送信本文を組み立て直して保存済みの台帳と SHA-256 を突き合わせ、検収、保存したコード化結果の読み込み、データセット作成、監査を行います。不合格の回答は、データセット作成より先に表示されます。自動テストはこのモードです。

2. **自分のPC・任意の接続先**: `config/demo.yaml`（`generation.base_url`、`generation.model`、必要なら `coding.*`）を編集し、順に実行します。

   ```
   python demo.py check
   python demo.py build
   python demo.py generate        # 送信します。モデルのサーバが必要
   python demo.py accept
   python demo.py code
   python demo.py dataset
   python demo.py audit
   ```

   既定のモデル名は `gpt-oss-20b` です。保存した回答は、研究用クラスタの NVIDIA H200（141GB）1枚で vLLM 0.30.0（`--reasoning-parser openai_gptoss`）を使って生成しました（`projects/demo_synthetic/RUN_RECORD.md`）。他の接続先では、必要な計算機の条件や推論部分の分離の仕方が異なる可能性があります（ここでは未確認）。鍵は設定に書かれた環境変数から読み、ファイルには書きません。

3. **Colab（無料GPU）**: この版では未対応です。後の段階で対応予定です。

### 再現性の2層

- **再生モード**: 送信した文面、その SHA-256、検収結果、データセットを厳密に再現します。
- **生成からやり直す**: 同じ手順で新しい標本を得ます。出力は保存したものと一致しなくてかまいません。接続先が違えば seed は同じ出力を保証しません。文章や雛形を直したときは、保存した回答がその文面のものでなくなるため、作り直しが必要です（再生モードは止まって知らせます）。

## 3. 装置の流れ

0. **入力**: 人物ごとの文章（`inputs/texts/<person_id>.md`、匿名化済み）、人物表（`inputs/persons.csv`）、雛形、設定。
1. **組み立て**（`build`）: ヘッダ + ペルソナブロック + シナリオ + 質問 + 出力形式を空行で連結します。組み立ての前に、雛形の全ファイルを `templates/frozen_hashes.csv` と照合します（一致しなければ止まります）。送信本文の SHA-256 を `ledger.jsonl` に記録します。条件は `C3`（本人の文章）、`C0`（ペルソナブロックなし）、`C3W`（次の人物の文章。1つずらす巡回）、`C3-mixed`（本人のエピソードを、文字数が最も近い他人物のエピソードで1つずつ置換。乱数なし）。
2. **生成**（`generate`）: 送信前にもう一度、台帳のハッシュと照合し、1通のユーザーメッセージとして送ります。temperature 1.0、top_p 1.0、max_tokens 8192、seed = `seed_base` × 100 + 反復番号。`reasoning_effort` は独立した設定で、記録されます。実際に送った本文と応答を1件1ファイルで保存します。
3. **検収**（`accept`）: 7つの形式規則（JSON として読める／キーがちょうど7つ／q1 は相異なる3記号／q2 の分類番号が範囲内／q3 は4択／q5 は5者の順列／自由記述3つが非空）。不合格は作り直さず、`rejects.csv` に記録します。
4. **コード化**（`code`）: 3つの自由記述を、変数ごとの別のプロンプトで分類・評定します。評定者に渡すのは当該の文だけで、人物・条件・モデル・シナリオは渡しません。コード化の接続先は生成と別に設定できます。既定では生成と同じモデルです（簡略化）。
5. **データセット作成**（`dataset`）: `dataset_A.csv`（1回の生成ごとに1行: `person_id, condition, model, scenario, rep, accepted`、構造化した回答、コード化の値）と `dataset_B.csv`（人物ごとに1行: `persons.csv` の列）。結合キーは `person_id`。`C0` の行は `person_id` が空です。
6. **監査**（`audit`）: 台帳・送信ファイル・出力記録を突き合わせ（件数とハッシュの一致数を表示）、あわせて雛形から本文を組み立て直して独立に照合します。

出力の値（選択肢など）は日本語のままです。

## 4. 本研究との対応（下書き）

| デモの段 | 本研究の工程 | 簡略化した点 |
|---|---|---|
| 組み立て・ハッシュ照合 | 凍結文面からの機械組み立て、送信前照合、台帳記録 | 同型（移植） |
| 生成 | 研究用クラスタ上の公開モデル、数千件 | 小さなモデル1つ、数十件。`reasoning_effort` は新しい自由度 |
| 検収 | 7規則、不合格は記録のみ | 同型 |
| コード化 | 別系統のモデル、4変数、当該文のみ | 既定は生成と同じモデル（分離可）。変数は同じ4つ |
| データセット | 別スクリプトで構築した大きなデータセット | 最小の2表 |
| 分析 | 混合モデル（人による照合の後） | **含まない** |
| 長期志向の測定 | 抽出→対比較→Bradley-Terry | **v1 では含まない** |

`templates/frozen_hashes.csv` の SHA-256 は、このリポジトリのファイルのハッシュです。本研究の凍結記録の値とは別物で、一致しません。本研究のコードブックは同梱していません（別途追加予定）。ここでの文章は3,000〜5,000字ほどで、本研究の文章よりずっと短いため、実行時間とモデルの挙動は異なります。

## 5. 自分のデータで使う

`projects/_template/README.md` を見てください。要点は、`projects/_template/` を `projects/<自分の名前>/` にコピーし、匿名化した文章を `inputs/texts/` に入れ、`inputs/persons.csv` を埋め、`config/demo.yaml` の `project:`（または `--project`）でそのフォルダを指し、`python demo.py check` を通すことです。
差し替えられるもの: 文章、属性の列、シナリオ・質問・出力形式のファイル、条件の選択、反復数、接続先、パラメータ。
この版で変えられないもの: 組み立ての順序、ハッシュの記録と照合、7規則の構造（値の集合だけ設定で変更可）、監査の型。
雛形のファイルを変えたときは、`frozen_hashes.csv` を意識して作り直してください。設定のパラメータは `generation_params.yaml` と一致している必要があります。

## 6. 限界と、確認していないこと

- 保存した回答（`outputs_example/`）は、実際の1回の実行（vLLM + gpt-oss-20b、GPU 1枚。`projects/demo_synthetic/RUN_RECORD.md`）から作りました。自動テストは今もダミーのクライアントと小さな固定データを使い、モデルには接続しません。
- Colab の無料枠で既定のモデルが動くか、他の接続先が推論部分を回答に混ぜないかは確認していません。保存した実行では、推論部分は別の欄で返り、回答に混ざったものはありませんでした。
- 保存した実行の 144 件のうち 2 件は、検収規則1（JSON として読めない。閉じ引用符が `"` ではなく `」` だった）で不合格でした。手順どおり `rejects.csv` に残し、コード化とデータセット A の合格行から外しています。
- 既定のコード化は生成と同じモデルです（簡略化）。
- 合成文章では、実データの知見が再現されることは示せません。
